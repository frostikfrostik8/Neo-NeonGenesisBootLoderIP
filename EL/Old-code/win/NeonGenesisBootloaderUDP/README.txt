Дата последнего обновления README - 25.11.2025

1. Обновление устройств:
    1.1. Обновление устройств через последовательный порт
        1.1.1 Обновление по интерфейсу RS485 (или через RS232) производится скриптами:
        (sudo ./update_X.sh $1 $2), где 
            X - наименование устройства (Chademo, CCS, GBT, GBT2, 2CAN, LCSC, BLCC)
            $1 - порт RS485
            $2 - файл прошивки (.bin)

        1.1.2. Обновление подпрограммы-трансивера производится в устройствах скриптами:
        (sudo ./update_X_transceiver.sh $1 $2), где
            X - наименование устройства (Chademo, CCS, GBT, GBT2)
            $1 - порт RS485
            $2 - файл прошивки (Transceiver_stable.bin)

        1.1.3. Обновление конфигурации в EEPROM производится в устройствах скриптами:
        (sudo ./update_X_eeprom.sh $1 $2), где
            X - наименование устройства (Chademo, CCS, GBT, GBT2)
            $1 - порт RS485
            $2 - файл прошивки (.ini)

        1.1.4. Обновление устройств по интерфейсу CAN производится через контроллеры скриптами:
        (sudo ./update_X_N_from_Y.sh $1 $2), где 
            X - наименование CAN-устройства (DIDO, BM, 2CAN, LCSC, BLCC)
            N - номер устройства
            Y - наименование контроллера (Chademo, CCS, GBT, GBT2)
            $1 - порт RS485
            $2 - файл прошивки (.bin)
    
    1.2. Обновление устройств по UDP
        1.2.1 Обновление LAN-RA:
        (sudo ./update_lanra_post_X.sh $1), где
            X - номер стойки
            $1 - файл прошивки (.bin)

        1.2.2 Обновление устройств через LAN-RA:
        (sudo ./X_post_Y.sh $1), где
            X - скрипт из п. 1.1
            Y - номер стойки
            $1 - файл прошивки (.bin)

        1.2.3 Обновление CAN-устройств напрямую через LAN-RA:
        (sudo ./update_X_N_by_lanra_post_Y.sh $1), где 
            X - наименование CAN-устройства (DIDO, BM, 2CAN, LCSC, BLCC)
            N - номер устройства
            Y - номер стойки
            $1 - файл прошивки (.bin)

        1.2.4 Обновление CCSEM3 (Type-2):
        (sudo ./update_type2.sh $1), где 
            $1 - файл прошивки (.bin)

        1.2.5 Обновление ESP32 через CCSEM3 (Type-2):
        (sudo ./update_esp32_by_type2.sh $1), где 
            $1 - файл прошивки ESP32 (.bin)

    1.3 Примеры и премечания
        Пример: sudo ./update_ccs.sh /dev/ttyS0 ChS-RA-04.v2_CdM_CCS_GBT_160kWt_2CAN_noCcsBoard_1.7.7_6.5.2025_3Ch_release.bin.
        Пример: sudo ./update_gbt_2.sh /dev/ttyS0 chS-ra-03_GBT_2_v1.3.9.bin
        Пример: sudo ./update_dido_0_from_ccs.sh /dev/ttyS0 ChS-RA-DIDO-03_19_02_2025.bin.
        Пример: sudo ./update_mira_1_from_gbt_2.sh /dev/ttyS0 ChS-RA-BM_09_06_2025.bin.
        Примечания: 
            1.3.1. Обновление любого модуля может производиться через любой контроллер CCS, GBT, GBT2 кроме 2CAN (update_dido_0_from_ccs.sh, update_dido_0_from_gbt.sh).
            1.3.2. Нумерация модулей DIDO в наименовании скрипта начинается с индекса 0 (update_dido_0_from_ccs.sh, update_dido_1_from_ccs.sh).
            1.3.3. Нумерация модулей MIRA в наименовании скрипта начинается с индекса 1 (update_mira_1_from_ccs.sh, update_mira_2_from_ccs.sh).
            1.3.4. Щбновление любого из контроллеров CCS, CCS2 производится через скрипт sudo ./update_ccs.sh.

2. Формирование скрипта
    Скрипт предстваляет собой последовательную остановку служб, вызов приложения для обновления с параметрами и запуск остановленных служб.
    2.1. Для обновления устройств через последовательный порт вызов приложения в скрипте формируется как: 
    (sudo ./EasyLoader X $1 $2), где
        ./EasyLoader - исполняемый файл (формируется в п.3);
        X - число, поряок формирования которого описан в п. 2.1.1 - 2.1.3
        $1 - параметр, который принимает порт при вызове скрипта;
        $2 - параметр, который принимает наименование файла прошивки при вызове скрипта.

    Число X может состоять из 1, 2 и 3 символов (3 разрядов в 16-ричн. сист. счисл.), то есть X = ABC:
        2.1.1. В качестве младшего символа С - всегда указывается slave ID прошиваемого контроллера, либо контроллера, через который прошивается другое устройство.
        С - может принимать следующие значения:
            1 - Type2;
            2 - Chademo;
            3 - CCS;
            4 - Type1;
            5 - GBT;
            6 - CCS2(Не поддерживается);
            7 - 2CAN;
            8 - GBT2;
            9 - CCS3(Не поддерживается);
            F - LAN-RA;
        
        2.1.2. В качестве второго символа B (если символа 2) - указывается функция прошивки устройства, установленного на контроллере.
        B - может принимать следующие значения:
            1 - Обновление трансивера;
            2 - Обновление EEPROM;
            3 - Обновление ESP32;
            F - Исключение - обновление модуля LCSC, в этом случаее разряд С - будет принимать значения (0 - 3), то есть BC = (F0 - F3)

        2.1.3. В качестве старшего символа A - ID устройства, обновляемого по шине CAN через контроллер.
        A - может принимать следуюшие значения:
            5 - DIDO;
            6 - BM;
            7 - 2CAN;
            8 - LCSC;
            9 - BLCC;    
        B - в таком случае - это номер устройства на шине CAN, екоторый может принимать значения 0-F
        Примечание: для DIDO (0 - 7), для BM (1 - 3), для LCSC и BLCC (0 - 3), для 2CAN (0)

    2.2. Для обновления устройств по UDP вызов приложения в скрипте формируется как:
    (sudo ./EasyLoader X [PORT] $1 [IP]), где
        ./EasyLoader - исполняемый файл (формируется в п.3);
        X - число, поряок формирования которого описан в п. 2.1.1 - 2.1.3
        $1 - параметр, который принимает наименование файла прошивки при вызове скрипта.
        [PORT] - UDP порт, по умолчанию 8007
        [IP] - IP-адрес прошиваемого устройства

    2.3. Примеры содержания скриптов.
        sudo ./EasyLoader 508 $1 $2 - update_dido_0_from_gbt_2.sh.
        sudo ./EasyLoader 18 $1 $2 - update_gbt_2_transceiver.sh.
        sudo ./EasyLoader 28 $1 $2 - update_gbt_2_eeprom.sh.
        sudo ./EasyLoader F2 $1 $2 - update_lcsc_2.sh.
        sudo ./EasyLoader f 8007 $1 192.168.1.21 - update_lanra_post_1.sh
        sudo ./EasyLoader 81f 8007 $1 192.168.1.21 - update_lcsc_1_by_lanra_post_1.sh
        sudo ./EasyLoader 5 8007 $1 192.168.1.23 - update_gbt_post_3.sh
    
3. Сборка приложения
    В папке ../NeonGenesisBootloader/src/ находятся исходники приложения, при изменении исходников нужно собрать исполняемый файл.
    3.1. Перейдите в папку "NeonGenesisBootloaderUDP\src" через консоль и выполните команду "sudo chmod 777 *".
    3.2. Выполните в этом каталоге скрипт "install.sh", а после завершения выполните скрипт "build_application.sh"
    3.3. Из появившейся папки "dist" скоопируйте исполняемый файл "EasyLoader" в папку "NeonGenesisBootloader".
    3.4. В папке "NeonGenesisBootloader" выполните команду "sudo chmod 777 *"и повторите прошивку устройства.
